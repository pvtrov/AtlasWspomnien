# User Stories

## Cel dokumentu

Ten dokument opisuje podstawowe user stories dla najważniejszych ról w systemie. Ich celem jest uporządkowanie prac nad funkcjonalnościami oraz ułatwienie planowania kolejnych etapów implementacji.

## Przeglądający

- Jako przeglądający chcę przeglądać dostępne zdjęcia, aby odkrywać historyczne materiały związane z wybranym obszarem.
- Jako przeglądający chcę wyszukiwać zdjęcia po frazie tekstowej, aby szybko odnaleźć interesujące mnie treści.
- Jako przeglądający chcę filtrować zdjęcia po lokalizacji, aby zawęzić wyniki do konkretnego miejsca.
- Jako przeglądający chcę filtrować zdjęcia po dacie lub zakresie dat, aby przeglądać materiały z wybranego okresu.
- Jako przeglądający chcę oglądać szczegóły zdjęcia, aby zobaczyć jego opis, datę oraz inne metadane.
- Jako przeglądający chcę przeglądać zdjęcia według struktury hierarchicznej, aby eksplorować archiwum w uporządkowany sposób.

## Twórca

- Jako twórca chcę założyć konto i zalogować się do systemu, aby zarządzać własnymi materiałami.
- Jako twórca chcę dodać zdjęcie do archiwum, aby udostępnić materiał innym użytkownikom.
- Jako twórca chcę opisać zdjęcie za pomocą podstawowych metadanych, aby było łatwiejsze do odnalezienia.
- Jako twórca chcę przypisać zdjęcie do odpowiedniej kategorii lub struktury hierarchicznej, aby było poprawnie uporządkowane.
- Jako twórca chcę edytować własne zdjęcie oraz jego opis, aby móc poprawić błędy lub uzupełnić informacje.
- Jako twórca chcę usunąć własne zdjęcie, aby móc wycofać materiał z archiwum.
- Jako twórca chcę widzieć listę swoich zdjęć, aby wygodnie nimi zarządzać.

## Administrator

- Jako administrator chcę usuwać wadliwe lub niepożądane zdjęcia, aby utrzymać jakość i wiarygodność archiwum.
- Jako administrator chcę edytować metadane i opisy zdjęć, aby poprawiać błędy oraz ujednolicać informacje w systemie.
- Jako administrator chcę blokować użytkownika przed dodawaniem nowych materiałów, aby ograniczać nadużycia.
- Jako administrator chcę przeglądać materiały i użytkowników, aby skutecznie zarządzać działaniem systemu.

## Uwagi do dalszego planowania

User stories z tego dokumentu stanowią bazę do:

- podziału prac na epiki i zadania techniczne,
- ustalenia kolejności implementacji,
- wyboru zakresu pierwszych iteracji projektu,
- późniejszego przygotowania backlogu rozwojowego.
